# ファウンドリ手順書

ファウンドリがモールドを受けてから納品するまでの手順。役割の関数は抽象クラスの「ファウンドリの中の人」、進行の段階は「進行」に対応する。

製造中に個人が詰まったときの行動は [foundry-member.md](./foundry-member.md) に置く。

## 1. モールドの検証と請書

モールドを受け取ったら、製造に入る前に 1-1 から 1-2 を行い、1-3 で結果を返す。

### 1-1. 必須項目の記入を確かめる

モールドの次の欄を上から順に見て、記入のない欄を不備に書き出す。

| 欄 | 記入ありとみなす状態 |
|---|---|
| モールドID | 識別子が書かれている |
| リビジョン | 番号が書かれている |
| 発行日 | 日付が書かれている |
| 期限 | 日付が書かれている |
| ファブレス | 書かれている |
| ファウンドリ | 書かれている |
| テストケース | 一件以上あり、各件にテストケースIDが振られている |

### 1-2. 期待結果があるか見る

- テストケースIDを一つずつ取り出す
- 期待結果が書かれているか見る
- 期待結果が、結果を見て満たしたか満たしていないかを決められる形で書かれているかを見る。判定が分かれる書き方であれば、不備に書き出す

### 1-3. AcknowledgeDecision か RejectDecision を返す

不備が一件もなければ、AcknowledgeDecision をファブレスに出す。Decision には次を書く。

- モールドID
- リビジョン
- 判断者
- 判断日時

AcknowledgeDecision を出すまで製造に入らない。

不備が一件でもあれば、AcknowledgeDecision は出さず、RejectDecision をファブレスに返す。不備のある項目と理由を一件ごとに書く。

| 項目 | 理由 |
|---|---|
| テストケース | TC-005 の期待結果がない |

ファブレスがリビジョンを上げて出し直したら、1-1 からやり直す。

## 2. 製造

AcknowledgeDecision を出したモールドを手元に置き、そのモールドだけを見てソースコードを作る。

- テストデータを受け取り、各テストケースの期待結果どおりの出力を返すものを作る
- 判断に使う値は、テストデータにあるものだけにする。テストデータにない値を読んだり参照したりする処理を書かない
- テストケースに書かれていない入力への対応を書かない。必要なら質問として出す
- モールドに書かれていない機能や挙動を足さない。足したくなったら、ファブレスに新しいモールドとして出してもらう
- ファブレスの内部事情、上長の意向、口頭の依頼など、モールドに書かれていない要因で実装を変えない

## 3. プルーフの作成

ソースコードができたら、Requirement Proof と Logic Proof を作る。

### 3-1. Requirement Proof を作る

- モールドIDとリビジョンを書く
- モールドのテストケースをIDの順に写し、一件ずつ応答を書く
- 各応答に、満たしている / 満たしていない / 適用外 のどれか一つを書く
- 満たしている応答には、ソースコードのどこで満たしているか（ファイル名と行、関数名など）を書く
- 適用外の応答には、なぜ適用外なのかを書く
- 満たしていない応答が残っている場合は、製造に戻って直す

### 3-2. Logic Proof を作る

- 各テストケースをテストコードにする
- テストデータを入力とし、期待結果を期待値とする
- テストを実行し、各テストケースの実行結果と実行日時を残す
- 実行に使った環境（言語やランタイムの版、依存ライブラリ、OS など）を書く

テストを書いただけで実行していないものは、Logic Proof として出さない。

## 4. 納品

- 次の三つが揃っているかを見る
  - ソースコード
  - Requirement Proof
  - Logic Proof
- 三つ揃っていれば、まとめて ShipDecision としてファブレスに出荷する
- 一つでも欠けていれば出荷しない。欠けているものを作ってから出荷する

出荷した時点で、そのモールドについてのファウンドリの責任は終わる。

## 5. 差し戻しへの対応

ファブレスから SendBackDecision が届いた場合に行う。

- 書かれたテストケースIDと理由を読む
- 該当するテストケースを満たすようにソースコードを直す
- 直したテストケースについて、Requirement Proof の応答と Logic Proof のテストを作り直し、テストを実行し直す
- 「4. 納品」の手順で、パレットを揃えて再び出荷する

差し戻しを受けてから再び出荷するまでは、ファウンドリの責任が続く。

## 6. 取り下げへの対応

ファブレスから WithdrawDecision が届いた場合に行う。

- 停止時点の状態を、そのままの状態でパレットにまとめる
- 「4. 納品」の手順で出荷する

## 7. ディシジョンの受領

ファブレスから届いたディシジョンについて、誰がいつ受け取ったかを記録する。

受領を拒むことはできない。異議は新たなディシジョンとして出す。

## 8. アンドンの設置

製造に入る前に、次の二つを用意する。

- 停止要因の申告を受けるアンドン
- 申告が入った時点でファウンドリ全体へ配信する通知

申告と引き受けの手順は [foundry-member.md](./foundry-member.md) に置く。
