# チュートリアル: ファブレス編(人間のチームを相手にする)

ファブレスがモールドを書き、人間のファウンドリに発注する一周を通す。

## 前提

- 参照: `manuals/fabless.md`, `manuals/foundry.md`, `templates/mold.md`, `templates/structs.md`
- ファウンドリ役を担う相手を一人以上用意する
- モールドを渡す以外の口頭・チャットでの補足を行わない

## 題材

商品コード文字列を検証する関数。

## 手順 1: モールドを書く

`templates/mold.md` を複製し、`manuals/fabless.md` の 1-1 から 1-4 に沿って埋める。

### 識別

- モールドID: `tutorial-team-01`
- リビジョン: 1
- 発行日: 記入する
- 期限: 記入する
- ファブレス: 自分
- ファウンドリ: 相手

### テストケース

| ID | シナリオ | 事前条件 | テストデータ | 期待結果 |
|---|---|---|---|---|
| TC-001 | 形式に一致 | なし | `{code: "ABC-1234"}` | `有効` |
| TC-002 | 数字がすべて 0 | なし | `{code: "XYZ-0000"}` | `有効` |
| TC-003 | 英字が小文字 | なし | `{code: "abc-1234"}` | `無効` |
| TC-004 | 英字が2文字 | なし | `{code: "AB-1234"}` | `無効` |
| TC-005 | 数字が5桁 | なし | `{code: "ABC-12345"}` | `無効` |
| TC-006 | ハイフンがない | なし | `{code: "ABC1234"}` | `無効` |
| TC-007 | 長さ1（下限） | なし | `{code: "A"}` | `無効` |
| TC-008 | 長さ20（上限） | なし | `{code: "ABCDEFGHIJKLMNOPQRST"}` | `無効` |

### 参照

- なし

## 手順 2: 発送する

書いたモールドを相手にファイルとして渡し、DispatchDecision を記録する。渡す際に口頭やチャットで補足しない。

補足したくなった内容が生じたら、手元に控える。控えた内容は、モールドに書けたはずのものである。

## 手順 3: 請書を待つ

相手から AcknowledgeDecision または RejectDecision が返る。

RejectDecision が返ってきた場合、`manuals/fabless.md` の 3 節に沿って直し、リビジョンを上げて出し直す。

## 手順 4: 納品を受け取り、検証する

ShipDecision が届いたら、`manuals/fabless.md` の 4-1 から 4-2 を行う。

Logic Proof を自環境で実行し直す。相手の環境で pass していても、自環境で再現できなければ差し戻す。

満たしていないテストケースがあれば SendBackDecision を出す。書くのは満たしていないテストケースIDと理由だけにする。

## 手順 5: 記録を残す

一周を終えたら次を記録する。

- 手順 2 で控えた「補足したくなった内容」の件数と内訳
- 差し戻しの有無と、その理由の分類(モールドの記述不足 / 実装のミス)
- AcknowledgeDecision が出るまでの時間、納品までの時間

## 読み取れること

手順 2 で控えた内容が、このチュートリアルの主な出力になる。

補足したくなったということは、モールドに書けていなかった何かがある。その内訳を見ると、自分のスコーピングがどこで足りなかったかが分かる。件数が多いほど、モールドが薄かったことになる。

AI を相手にした場合と違い、人間のファウンドリは書かれていない部分を経験で埋める。埋められたことに気づかないまま納品されることもある。差し戻しが起きなかったからといって、モールドが十分だったとは限らない。控えた内容と突き合わせて判断する。
